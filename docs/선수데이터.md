# 선수 데이터 — FM식 데이터 모델 (최종)

- 작성: 엔진 총괄 기획 · 2026-10-23 · 이 파일: `docs/선수데이터.md`
- 짝 문서: `docs/경기엔진.md`(이 데이터를 엔진이 읽는 길) · `docs/기획서.md`(카드 등급·레벨·강화·조합) · `docs/날씨.md` · `docs/이벤트.md`
- 기계가 읽는 정의: `fd/out/15_player_schema.json`(능력치 정의·아키타입 평균/표준편차·요인 상관·성장 곡선·부상 표·특성 규칙·검증) — 엔진·서버·도구는 이 JSON 을 읽는다. 코드: `shared/engine/player.ts`(읽기), `generate.ts`(생성·OVR·카드 6칸).
- 이 문서가 **'진짜 기준'**이다. 카드에 보이는 숫자(대표 6칸·OVR)는 여기서 계산한 요약이고, 카드 층·조합 층 보너스는 여기 정의된 깊은 능력치에 점수로 더해진다.

---

## 1. 한눈에 보기

1. **진짜 값은 하나, 렌즈는 셋.** 능력치는 1.0~100.0(0.1 단위, int16×10)으로 한 번 저장하고, 카드 앞면 1~99 · 상세 화면 FM 1~20 색 표 · 스카우트 보고서 20~80 으로 같은 값을 다르게 보여 준다. 60 = 1군 그 포지션 평균 주전, 1군 주전끼리 표준편차 약 10.
2. **보이는 능력치 45개**: 타격 8 + 번트 + 성향 3 · 주루 4 · 수비 6 + 포수 4 · 투구 9 + 땅볼 성향 · 정신 6 · 신체 3. 여기에 **포지션 숙련 10칸**(1~20), **구종 2~5개**(구종마다 위력·커맨드·구사율, 시그니처 구종), 팔 각도, 타격·투구 폼.
3. **숨은 능력치 13개**(기복·큰 경기·압박감·부상 경향·다재다능·적응력·프로의식·기질·야망·충성심·스포츠맨십·구설·자존심) + **날씨 특성 6개**(내열·내한·우천·주간 시야·바람 판단·박명 시야), 1~20. 존재·이름·효과 식은 도움말에 공개하고 숫자만 관찰로 드러난다(숨긴다 ≠ 속인다).
4. **성격 24종**(숨은 능력치 조합의 이름표)과 **특성 37개**(엔진 파라미터를 직접 바꾸는 습관, 선수당 최대 4개) — 지금 엔진이 34개를 동작으로 구현했다.
5. **카드는 요약**: 대표 6칸(타자 컨택·파워·선구·주루·수비·어깨 / 투수 구속·구위·변화·제구·체력·멘탈)은 깊은 능력치의 가중 묶음, OVR 은 6칸의 포지션별 가중합. 화면 숫자를 손으로 검산할 수 있다.
6. **세 층**: 진짜 층(나이·출장·훈련으로만 변함) · 카드 층(레벨·강화·스타일·각인·장비·각성) · 경기 층(팀컬러·유닛·케미·지휘·폭발 + 컨디션·사기·날씨·상황). 층을 따로 들고 있어 '원인 표시'(↳ 강화 +6 덕분)를 같은 난수로 다시 계산할 수 있다.
7. **보너스는 선형으로 더한다**(기획서 결정, 엔진 문서 3.4). '전 능력' 보너스는 성향 외 41개 능력치 + 구종 위력·커맨드 전부에, '묶음' 보너스는 그 카드 칸을 이루는 능력치에만 같은 점수를 더한다.
8. **포지션 적성은 숙련 하나로**: 카드의 ◎○△×⚠ 기호와 수비 배율은 모두 진짜 숙련(1~20)에서 계산한다.
9. **생성**: 아키타입 26개 × 잠재 요인 모델(타자 7·투수 5·성격 4 요인, Cholesky) → "파워↑ 컨택↓", "체중↑ 스피드↓", "나이↑ 선구안↑" 같은 상관이 저절로 나온다. 1,000명 생성 검증 통과, KBO 기록 분석(19)으로 곡선·비율을 고친다.
10. **성장·노화**: CA/PA(1~200) + 능력치마다 다른 곡선 13개 + 성장 유형 4가지 + 주 1회 성장식. 커리어 시즌이 흐르면 카드의 진짜 값이 `trueDelta` 로 변한다(카드 목록은 그대로).
11. **부상**: 노출 13종(질주·스윙·투구·사구·슬라이딩·다이빙·포수 이닝 …) × 부상 26종. 팀·시즌 결장 부상 16.9건(목표 18±4), 15일 이상 6.6건, 시즌 아웃 0.49건.
12. **저장**: 인물 1명 약 1.2KB(JSON)·약 200B(이진), 엔진 입력 `PlayerIn` 은 경기 직전 서버가 조립한다.

## 2. 원칙

### 2.1 렌즈

| 렌즈 | 식 | v=45 | v=60 | v=72 | v=85 | 어디에 |
|---|---|---|---|---|---|---|
| 카드 1~99 | round(v) | 45 | 60 | 72 | 85 | 카드 앞면·OVR·대표 6칸 |
| FM 1~20 | round(v/5) | 9 | 12 | 14 | 17 | 상세 화면(1~5 빨강·6~10 주황·11~14 노랑·15~17 연두·18~20 초록) |
| 스카우트 20~80 | round5(v − 10) | 35 | 50 | 60 | 75 | 스카우트 보고서 "파워 50/65(현재/미래)" |

- 눈금 뜻: 30 = 2군 후보, 45 = 2군 평균, **60 = 1군 그 포지션 평균 주전**, 70 = 올스타 후보, 80 = 리그 정상급, 90 = 역대급.
- 진짜 값은 100 을 넘지 않는다(성장도 75 위에서는 ×(100−v)/25 로 둔화). 100 을 넘는 숫자는 카드·조합 층이 더한 '금색 숫자'(기획서 3.1, 칸 상한 130)이며 엔진은 90 위를 소프트캡한다.
- 숨은 능력치·날씨 특성은 FM 처럼 1~20 정수(10 = 보통). 성향 4개는 방향(1~100, 50 중립)이라 OVR 에서 빠진다.

### 2.2 세 층 (섞지 않는다)

| 층 | 내용 | 언제 바뀌나 | 저장 위치 |
|---|---|---|---|
| 진짜 층 | 능력치 45 · 숙련 10 · 구종 · 숨은 19 · 특성 · 폼 · 키·몸무게·투타·팔 각도·나이 | 커리어 성장·노화(주 1회), 코치 훈련(특성·폼), 부상 후유증 | 카탈로그 인물 + 유저 카드 `trueDelta` |
| 카드 층 | 레벨·경험치·강화·플레이스타일·완성 각인·장비·각성·수상 각인 | 유저 육성 | 유저 카드 행 |
| 경기 층 | 팀컬러·유닛·케미·지휘·품격·폭발 / 큰 경기·홈·적응·통증 / 상태(컨디션·피로·팔·감각·자신감·사기·폼) / 날씨 | 라인업·경기·경기 사이 | 라인업 계산(서버 공용 함수)·리그 상태 |

### 2.3 숨긴다 ≠ 속인다

- 도움말에 숨은 13 + 날씨 6 의 **이름·뜻·효과 식을 전부 공개**한다. 값은 경기 관찰·스카우트 지식으로 점점 드러난다(10절).
- 효과는 작게(큰 경기 최대 ±3.6점, 압박감 최대 ±2.4점, 날씨 특성 판정별 ±5% 상한)·원인 표시로 체감시킨다. 원작들의 '히든 스탯 부정 → 조작 의혹' 문제를 규칙 공개로 푼다.

## 3. 레코드 구조

### 3.1 저장 단위

| 단위 | 키 | 내용 | 크기 |
|---|---|---|---|
| 인물(카탈로그) | `personId` | 이름(가상)·구단·고향·국적·생년·투타·팔 각도·키·몸무게·주 포지션·아키타입·성장 유형·능력치 45(int16×10)·숙련 10·구종·시그니처·폼·숨은 19·특성·PA·부상 이력 | JSON 약 1.2KB, 이진 약 200B |
| 카드(목록 v1, 1,042장) | `cardId` | 인물 + 발행 시즌 스냅숏(그 시즌 나이의 진짜 값) + 등급 + `base`(발행 6칸) + `growth`(성장 1단계당 6칸, 0.1 단위) + `startLevel`·`maxLevel` | 카드 목록 파일(고정) |
| 유저 카드 | `userCardId` | `cardId` · 레벨·경험치 · 강화 · 스타일 · 각인 · 장비 · 각성 · 수상 각인 · `games1`(1군 경기 수) · `trueDelta`(커리어 성장·노화 변화량, 2차) · 잠금 | D1 한 행 |
| 경기 상태(시즌) | (리그, pid) | 컨디션·피로·팔·감각·자신감·사기·폼 플래그·연투 3일·적응 경기·부상 남은 일 | 리그 상태 JSON 안 |

- OVR·대표 6칸·포지션별 OVR·성격 이름은 **계산값**(저장 안 함, 목록 정렬용 OVR 만 캐시 칼럼).
- 같은 인물의 여러 카드(시즌·등급별)는 진짜 값이 다를 수 있다(그 시즌 스냅숏). 경기에서 쓰는 진짜 값 = 그 카드의 스냅숏 + `trueDelta`.

### 3.2 엔진 입력 `PlayerIn` (`shared/engine/types.ts`)

```ts
interface PlayerIn {
  id: number; age: number; throws: 'R'|'L'; bats: 'R'|'L'|'S';
  heightCm: number; weightKg?: number; armSlot?: 'over'|'threeQuarter'|'side'|'under';
  attrs: ArrayLike<number>;     // 45개, 4절 순서, 1~100(소수 가능)
  pos: ArrayLike<number>;       // 숙련 1~20: P,C,1B,2B,3B,SS,LF,CF,RF,DH
  pitches?: { t: PitchKey; stuff: number; cmd: number; use: number; sig?: string }[];
  hidden?: ArrayLike<number>;   // 숨은 13 + 날씨 6 (7절 순서), 1~20
  traits?: string[];            // 특성 id(최대 4)
  sigBat?: string;              // 시그니처 타격 특기
  bonus?: ArrayLike<number>;    // 카드 층 + 조합 층 보너스 점수(경기엔진 3.3) — 길이 48 목표(지금 47)
  mech?: MechBonus;             // 메커니즘형 조합 효과
  state?: PlayerState;          // 경기 직전 상태(9절)
  parkGames?: number;           // 이 구장 출장 수(구장 숙련)
  role?: 'SP'|'RP'|'CL';
  formFx?: Record<string, number>;   // 폼 효과 중 엔진이 직접 읽는 것(zoneSizeMult)
}
```
- 서버가 경기 직전에 (카드 스냅숏 + `trueDelta`) → `attrs`, (카드 층 + 조합 층) → `bonus`, (리그 상태) → `state` 로 조립한다. 엔진은 카드 등급·레벨을 모른다.

## 12. 성장·노화 (커리어, 2차)

```
주 1회(시즌 30주) + 비시즌 묶음 1회(8주 분량, 훈련 초점). 노화는 52주에 나눠 적용.

         × 출장(1군 주전 1.0 · 백업 0.8 · 2군 주전 0.85 · 미출장 0.55 · 부상 0.2) × 훈련 초점(×1.3 / 나머지 ×0.9) × 코치(0.85 + 0.015·등급) × 사기(0.9~1.1) × 멘토 1.05 × 잡음
여유 r = clamp((PA − CA)/24, 0, 1)^0.6 · 75 넘으면 × (100 − v)/25
연 하락 = 곡선 하락(나이) × (1.25 − 0.025·프로의식) × 성장 유형 배율 × (최근 2년 중증 부상 1건당 +10%) × (포수 스피드·범위 ×1.15) × 잡음
각성(성장 돌파): 25세 이하 시즌당 2% × (프로의식/10) — 핵심 2~3개 +3~6, PA +6 (이벤트 form_breakthrough)
```
