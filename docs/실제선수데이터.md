# 실제 선수 데이터 — 바뀐 이름 · 고정 ID · 카드 카탈로그 · 기록 화면

- 이 파일: `docs/실제선수데이터.md` · 짝 문서: `docs/선수데이터.md`(능력치 키 · 카드 6칸 · OVR), `docs/기획서.md`(등급 · 확률)
- 만드는 곳: `tools/kbo/build_kbo.py`(카탈로그) · `tools/kbo/names.py`(이름 규칙 — 한 곳) · `tools/kbo/awards.py`(수상 틀) · `tools/kbo/verify_kbo.py`(검증)
- 읽는 곳: `web/src/game/kbo.ts`(본체 · 카드 · 보기 · 선수단 · 상세 기록 불러오기)
- 기록 출처: **나무위키(CC BY-NC-SA 2.0 KR)** — 선수 기록 화면 아래와 설정 맨 아래에 작게 적는다.

## 0. 다시 만들기 (스크립트 한 번)

```
py -I -X utf8 tools/kbo/build_kbo.py  [--kbo <파싱 결과 폴더>]   ← 카탈로그 (수상 틀은 처음만 몇 분, 그다음은 로컬 캐시)
py -I -X utf8 tools/kbo/verify_kbo.py --rebuild                   ← 실명 0 · 이름 충돌 0 · 매핑 누락률 · 같은 입력 → 같은 출력
cd web && node scripts/run-ts.mjs scripts/kbo.test.ts <옛 저장 fixture.json>   ← 옛 보유 카드 이전 · 시작 선수단 종합 · 연도팩/구단팩
```

- 입력(이 컴퓨터에만 — 실명이 있어 저장소에 넣지 않음): 나무위키 선수 문서 파싱 결과 `players_list.tsv` · `players.csv` · `seasons_batting.csv` · `seasons_pitching.csv` · `raw/*.html`(수상 틀만 읽음).
  수집·파싱 규칙은 그 폴더의 README(나무위키 `/w/` 경로만, 요청 간격 3초 등).
- 출력(저장소): `web/src/game/data/kbo/core.json` · `rec-0.json`~`rec-f.json` · `tools/kbo/out/report.json`(규모·누락, 실명 없음).
  실명↔바뀐 이름 표는 입력 폴더 옆 `kbo_build/name_map.local.tsv` 에만(로컬 전용).

## 1. 데이터 모델 — 두 층

| 층 | 무엇 | 어디 | 한 번만 저장 |
|---|---|---|---|
| ① 선수 본체 | 고정 ID · 바뀐 이름 · 출생 연도 · 투타 · 팔 각도 · 외국인 · 키 · 몸무게 · 입단 연도 · 주/다른 포지션 + **카드가 생기는 시즌 목록**(연도 · 구단 코드 · 그 해 종합 · 등급 · 포지션/보직 · 나이 · 능력치 8/6칸 · 그 해 기록 요약) | `core.json` persons | 예 |
| ② 카드 종류 | 선수 ID + 시즌(또는 연도 없음) + 등급 + 구단 코드 + 카드 종합 + 능력치를 가져올 시즌 + (수상 부문 · 계보 기간) | 시즌 카드는 ①의 시즌 목록에서 만들고(같은 것을 두 번 적지 않음), 수상·상징 카드만 `core.json` cards | 예 |
| ③ 상세 기록 | 연도 × 구단(시즌 중 이적은 구단별 줄) 타격·투구 전부 + WAR — 카드 없는 시즌 포함 | `rec-<선수 ID 둘째 글자>.json` 16개 | 예 |

- 카드는 선수 정보를 복사하지 않는다. 화면·엔진이 쓰는 `Player` 는 (선수 ID, 시즌)마다 그때그때 만드는 **보기**(id `k1a2b3c~2016`)이고 저장하지 않는다.
- 보유 카드(`bb.inv` v2)는 카드 id 로만 들고, 카드 → 선수 본체는 ID 로 찾는다 (`game/mock.cardById`·`playerById` 가 `game/kbo` 를 찾아 씀).
- **선수풀 규칙**: 파싱한 선수 중 KBO 1군 시즌이 있고, 그중 **카드가 생기는 시즌(타석 30 이상 또는 10이닝 이상)이 하나라도 있는 선수**만 본체를 둔다.
  1군 기록이 없거나(퓨처스만·표 없음) 출장이 그보다 적은 선수는 넣지 않는다(카드가 없으면 화면에서 갈 길이 없음). 그 선수들의 짧은 시즌 기록은 버린다.

## 2. 이름 규칙 (`tools/kbo/names.py`)

- 성(첫 글자)은 그대로, **이름의 한 음절에서 자모 하나**만 바꿔 알아볼 수 있게. 외국인(띄어 쓴 표기)도 같은 방식(마지막 한글 음절부터).
- 단계(낮은 단계부터, 같은 단계면 마지막 음절부터 앞으로): ① 모음 짝 ㅏ↔ㅑ ㅓ↔ㅕ ㅗ↔ㅛ ㅜ↔ㅠ ㅐ↔ㅔ ㅒ↔ㅖ ㅘ↔ㅝ ㅙ↔ㅞ ㅚ→ㅙ
  ② 받침 ㄴ↔ㅇ ㄱ→ㅇ ㄹ→ㄴ ㅁ→ㄴ ㅂ→ㅁ ㅅ→ㄷ (없음→ㄴ) ③ ㅣ→ㅟ ㅡ→ㅜ ㅢ→ㅡ ㅟ→ㅜ ④ 받침 두 번째 후보 ⑤ 첫소리 짝 ㄱ↔ㅋ ㄷ↔ㅌ ㅂ↔ㅍ ㅈ↔ㅊ … ⑥ ①+② 함께.
- 바뀐 이름은 (가) 목록의 실제 이름 전체와 다르고 (나) 특별 선수 11명 이름과 다르고 (다) 다른 선수의 바뀐 이름과 달라야 한다 — 아니면 다음 후보.
  동명이인은 pid 순으로 앞 사람부터 후보를 받는다. 무작위 없음(같은 입력 → 같은 출력).
- 특별 선수 11명(`world.SPECIAL_PLAYER_NAMES`)은 바꾸지 않고, 실제 기록과 잇지 않는다(실제 선수 중 같은 이름이 있어도 그 선수는 바뀐 이름으로 따로).

## 3. ID · 카드 id 규칙

- **선수 ID** = `k` + SHA-1("kbo-person:" + pid) 앞 6자리 (겹치면 7·8자리). pid = 나무위키 문서 이름의 SHA-1 앞 10자리. 이름 규칙을 바꿔도 ID 는 그대로.
- **카드 id** = 선수 ID + 연도/종류 + 등급:
  - 시즌 `k1a2b3c-2016n|s|r|e` (노멀·스페셜·레어·엘리트 — 한 사람 한 해 한 장)
  - 수상 `k1a2b3c-2016mvp` · `k1a2b3c-2016gg` · `k1a2b3c-2016th-hr`(부문 코드 W·HR·AVG·RBI·ERA·SO·SV·SB·H·R·OBP·SLG·WPCT·HLD)
  - 상징 `k1a2b3c-lg` · `-fr` · `-bk` · `-sg` (한 사람 하나)
- 옛 가상 선수 카드(`c01`… · `k-구단-NN` · `kd-d-구단-n` · `x-구단-연도-…` · `g-…`)는 **레거시**로 그대로 둔다(아래 7절).

입력의 계보 코드(파싱 단계에서 붙인 franchise — 실제 구단 이름은 저장소에 적지 않는다) × 연도 → 가상 코드:

| SS | DG |
| LT | BS |

| OB | DDG (~1998) · SB (1999~) |
| LG | SCR (~1989) · ST (1990~) |
| HH | HBE (~1993) · DJ (1994~) |
| HD | ISB (~1985 전기) · IJR (1985 후기~1987) · IDR (1988~1995) · SUC (1996~2007) — 1985 은 1982~84 표기로 시작하면 전기 |

## 5. 등급 · 카드 생성 규칙

| 묶음 | 등급 | 몇 장 · 어떻게 |
|---|---|---|
| 시즌 | 노멀·스페셜·레어·엘리트 | 카드가 생기는 시즌(타석 30+ · 10이닝+)마다 1장. 그 해 리그 안 **성적 점수 백분위**(타자·투수 따로): 상위 6.7% 엘리트 · 다음 10% 레어 · 다음 30% 스페셜 · 나머지 노멀 (기획서 5.2의 20·30·90·160 비율) |
| 수상 | MVP · GG · TH | 나무위키 수상 틀(‘KBO 리그 MVP 수상자’ · ‘KBO 골든글러브 ○○ 부문 수상자’ · ‘KBO 리그 역대 ○○ 1위’)에서 연도별 수상자. 틀에 없는 (부문, 연도)만 우리 기록 1위로 계산(규정 타석 3.1×경기 · 규정 이닝 1×경기). 그 해 1군 기록이 있어야 카드 |
| 상징 | 시그니처 · 블랙 · 프랜차이즈 · 레전드 | 구단 계보(12줄)마다 ‘그 계보에서 쌓은 가치’ 순: 1위(8시즌+) 시그니처 · 다음 2명(6시즌+) 블랙 · 다음 6명(10시즌+) 프랜차이즈. 나머지 중 엘리트 시즌 2번 이상인 선수의 통산 가치 상위 약 4%가 레전드(카드 연도 = 가장 좋았던 시즌 = 황금기). 한 사람 상징 카드 하나 |

- **성적 점수**: 타자 = 타석/600 × (OPS+ − 72) × 0.75 + 포지션 보정(포수 +9 · 유격 +7 · 2루·중견 +4 · 3루 +2 · 우익 −2 · 좌익 −3 · 1루 −4 · 지명 −7, 600타석당) + 도루 × 0.15.
  투수 = 이닝/9 × (대체 평균자책 − 평균자책) + (세이브 + 홀드 × 0.5) × 0.12, 대체 평균자책 = 리그 평균자책 × 1.28(선발) / 1.18(구원).
  리그 평균은 `club-seasons.json` league(타율·평균자책)와 우리 기록의 앞뒤 2년 가중 평균.
- 한 선수가 여러 장을 가진다: 예) ’15 레어 · ’16 엘리트 · ’16 MVP · ’16 TH 홈런왕 · 레전드.

## 6. 능력치 (1~100) · 종합

- **모양은 성적에서, 높이는 백분위에서**. 그 해 리그 평균 대비 z 점수(표준편차는 전체 주전 묶음), 출장이 적으면 평균보다 조금 낮은 쪽으로 당김(타자 신뢰도 = 타석/(타석+220), 투수 = 아웃/(아웃+240)).
  - 타자 8칸: 컨택 = 0.75·z(타율) − 0.25·z(삼진%) · 파워 = 0.55·z(순장타) + 0.45·z(홈런%) · 갭 = 0.7·z(2·3루타/타수) + 0.3·z(순장타) · 선구 = z(볼넷%) · 삼진 회피 = −z(삼진%) ·
    스피드 = z((도루 + 2×3루타)/출루) − 나이 31+ 감점 · 수비·어깨 = 포지션 평균 + 체격(BMI) + 스피드 조금 − 나이 감점(수비 기록이 없어서).
  - 투수 6칸: 구속 = 0.65·z(9이닝 삼진) + 0.15·z(평균자책) − 옛 시대(1995 전 −6, 2008 전 −3) · 구위 = 삼진·피홈런·피안타 · 변화 = 삼진·평균자책·피안타 · 제구 = −z(9이닝 볼넷) ·
    체력 = 경기당 이닝(선발/구원) · 위기관리 = 평균자책·피홈런. 사이드암·언더핸드는 구종표가 다름.
  - 칸 값 = 60 + 10 × z, 그 뒤 **종합에 맞춰 평행 이동**(포지션별 가중 평균이 그 시즌 종합에 오도록 × 0.9).
- **시즌 종합(OVR)** = 백분위 → 노멀 56~70 · 스페셜 70~77 · 레어 77~83 · 엘리트 83~92 (기존 가상 선수 분포와 맞춤).
- **카드 종합**: 시즌 카드 = 시즌 종합. MVP = 시즌 +4(89~96) · GG +2(82~92) · TH +2(84~93). 상징 = 등급 안 순위로 레전드 84~90 · 프랜차이즈 86~92 · 블랙 89~94 · 시그니처 92~97.
- 상세 능력치 45개(`docs/선수데이터.md` 키)는 8/6칸에서 `game/kbo.buildAttrs` 가 결정적으로 펼친다(선수 ID·연도 해시로 ±몇 점). 카드 앞면 6칸은 목업과 같은 식.
- 레어 이상 투수 카드는 고유 구종(선수 ID 해시로 이름 약자형/별칭형).
- 시작 선수단: 다른 9개 구단의 최근 세 시즌 노멀·스페셜 카드에서 자리·목표 종합에 맞는 22장 + 지명 3(내 구단 최근 젊은 선수, 종합 64~78) + 특별 선수 → **팀 종합 65~68** (시험 3번, 20개 구단 모두).

## 7. 옛 보유 카드 (레거시)

- 보유 카드 저장 `bb.inv` 를 v2 로 올렸다. **v1(가상 선수 시절) 저장은 지우지 않고 그대로 v2 로 옮긴다** — 카드 · 수량 · 강화 · 실패 보정 · 라인업 · 통계를 그대로 두고,
  그때의 시작 설정을 `legacy.start` 에 적어 레거시 기본 선수단 카드를 같은 시드로 다시 만든다(`game/legacy/starter.ts` · `game/legacy/history.ts` 는 옛 생성기 그대로).
- v1 저장이 있던 기기는 시작 선수단도 레거시 그대로(`bb.starterKind`), 구단을 다시 고르거나(개막) 다시 창단하면 실제 선수 선수단으로 — 레거시 카드는 계속 보유·사용.
- 검증: 옛 커밋(b795765)의 코드로 만든 v1 저장(팩 60개 · 조합 · 강화 도전 — `web/scripts/legacy-fixture.ts`)을 새 코드로 읽어 **카드 종류 · 보유 수량 합 · 받은 장수 · 카드마다 이름·등급·종합이 같음**(시험 1번).

## 9. 크기 · 불러오기

- `core.json`(본체 + 시즌 요약 + 수상·상징 카드)은 첫 묶음(index)에 넣지 않고 따로 `kbo-core` 파일로 나뉜다(vite manualChunks) — 앱이 뜰 때 함께 받는다(모든 카드 화면이 쓰므로).
- `rec-0`~`rec-f`(연도별 상세)는 선수 ID 둘째 글자별 16개 — 선수 정보 ‘실제 기록’ 탭을 열 때 그 선수 파일 하나만.
- 규모·바이트는 `tools/kbo/out/report.json` (빌드할 때마다 갱신).
